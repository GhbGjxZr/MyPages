Gitee 上传教程

纯 Git 指令 · 每条命令讲清「做什么 / 不做什么」
五步上传，够用就行
1
git init
做什么 在当前文件夹创建一个空的 Git 仓库（生成隐藏的 .git 目录），让 Git 开始管理这个文件夹。
不做什么 不上传任何文件，不连接 Gitee，只是本地初始化。文件夹里原有的文件不会被改动。
2
git add .
做什么 把当前文件夹里所有新增和修改过的文件加入「暂存区」，告诉 Git：这些改动我准备提交了。
不做什么 没有真正保存版本，也没有上传到 Gitee。只写 git add 文件名 就只暂存那一个文件。
3
git commit -m "首次提交"
做什么 把暂存区里的内容打包成一个「版本」，存入本地 Git 仓库，并附上说明文字。
不做什么 仍然只存在于你的电脑上，没有上传到 Gitee。引号里的文字只是备注，不影响代码。
4
git remote add origin 你的仓库HTTPS地址
做什么 给本地的 Git 仓库绑定一个「远程仓库」地址，并起名叫 origin，之后 push 就知道往哪送。
不做什么 不上传代码，不下载代码，只是登记一个地址。若之前绑定过，需改用 git remote set-url origin 地址。
5
git push -u origin master
做什么 把本地仓库里已提交的版本上传到 Gitee 的 master 分支，-u 记住这次关联，以后直接 git push 即可。
不做什么 不会自动帮你 commit，没提交的改动不会被传上去；也不会拉取远程已有内容。
顺序不能乱：init → add → commit → remote → push。跳步会导致推送失败。

0. 先搞清楚 Git 和 Gitee 的关系

Git 是本地版本控制工具，负责记录代码的每次修改；Gitee 是基于 Git 的代码托管平台。
简单说：Git 管本地，Gitee 管远程。下面所有命令都在本地终端（Git Bash）执行。

1. 安装与配置（只需一次）
git --version
做什么 查看 Git 是否安装成功，显示版本号即表示已安装。
不做什么 不修改任何配置，不联网，只是查看。
git config --global user.name "你的名字" git config --global user.email "你的邮箱@example.com"
做什么 设置全局用户名和邮箱，Git 在提交时会记录「是谁提交的」，建议与 Gitee 账号一致。
不做什么 不创建仓库，不上传代码，只是写进 Git 配置文件。--global 表示对这台电脑所有仓库生效。
2. 完整上传流程（逐条讲清）
# 进入你的代码文件夹后执行 git init
做什么 在当前目录初始化一个本地 Git 仓库，生成隐藏文件夹 .git，从此 Git 可以追踪此目录下的文件变化。
不做什么 不上传、不提交、不关联远程仓库；已有文件不会被删除或移动。
git add . # 或指定文件： git add index.html
做什么 把工作区中所有新增、修改的文件放入「暂存区」，表示这些改动即将被提交。
不做什么 不生成版本记录，不上传远程。它只是「选中」改动，真正的存档在下一步 commit。
git commit -m "首次提交：完成基础页面"
做什么 将暂存区内容打包为一个版本，永久记录在本地 Git 历史中，-m 后是本次提交的说明。
不做什么 仍然只在本地，不会出现在 Gitee 上；也不包含没有 git add 过的改动。
git remote add origin https://gitee.com/你的用户名/仓库名.git
做什么 把本地仓库与 Gitee 上的远程仓库关联，给这个远程地址起别名 origin，方便后续 push/pull。
不做什么 不传输任何代码，只是登记地址。如果提示 remote origin already exists，改用 git remote set-url origin 新地址。
git push -u origin master
做什么 把本地 master 分支的所有已提交版本上传到 Gitee 的 origin 仓库；-u 建立跟踪关系，以后直接 git push 即可。
不做什么 不会自动 commit，未提交的改动不会被上传；不会自动合并远程已有内容（若远程有 README 等需先 pull）。
如果推送被拒绝（rejected），说明远程有本地没有的提交。先执行 git pull origin master 合并，再重新 push。
3. 日常更新：改完代码后只需三条
git add . git commit -m "修改说明" git push
做什么 暂存改动 → 提交到本地 → 推送到 Gitee。因为第一次 push 用了 -u，之后可以直接 git push，无需再写 origin master。
不做什么 不需要重复 git init 和 git remote add，一个仓库只需初始化一次。
4. 常见问题
❓ push 被拒绝 (rejected)

远程仓库有你本地没有的内容（如创建时勾选了 README）。先 git pull origin master 合并，再 git push。

❓ 每次都要输密码

在 Gitee 设置里配置 SSH 公钥，把远程地址换成 SSH 格式（git@gitee.com:...），即可免密。

❓ 提交后发现漏了文件

再执行 git add 漏掉的文件 → git commit -m "补充" → git push 即可，不需要重新 init。
