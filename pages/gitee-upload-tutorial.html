Gitee 上传教程

纯 Git 指令 · 每条命令讲清「做什么 / 不做什么」
⚠️ 注意：创建 Git 仓库后，Gitee 页面上会显示一段完整命令，只需复制修改即可
创建仓库后，Gitee 页面上有现成的命令，复制修改就能用，先看看注意事项
六步上传，够用就行
1
git init
做什么 在当前文件夹创建一个空的 Git 仓库（生成隐藏的 .git 目录），让 Git 开始管理这个文件夹。
不做什么 不上传任何文件，不连接 Gitee，只是本地初始化。文件夹里原有的文件不会被改动。
2
touch .gitignore
做什么 用 touch 创建一个空的 .gitignore 文件，准备写入需要忽略的内容。
不做什么 不会自动填写忽略规则，文件是空的；不删除任何已有文件。
3
vim .gitignore
做什么 用 Vim 打开 .gitignore，准备写入忽略规则。
不做什么 Vim 只是编辑器，不会自动修改文件，需要手动操作。
Vim 操作 重点 1. 按 i 进入插入模式
2. 输入忽略内容，例如：
    *.log
    *.exe
    go.mod
    go.sum
    .idea
3. 按 Esc 退出插入模式
4. 输入 :wq 保存并退出
5. 如果不想保存，输入 :q! 强制退出
重定向 备选 如果不想用 Vim，可以用重定向直接写入：
echo "*.log" > .gitignore  （覆盖写入）
echo "*.exe" >> .gitignore  （追加写入）
echo "go.mod" >> .gitignore
echo "go.sum" >> .gitignore
echo ".idea" >> .gitignore
说明：> 会清空原文件再写入，>> 在文件末尾追加内容。
4
git add .
做什么 把当前文件夹里所有新增和修改过的文件加入「暂存区」（忽略文件除外），告诉 Git：这些改动我准备提交了。
不做什么 没有真正保存版本，也没有上传到 Gitee。只写 git add 文件名 就只暂存那一个文件。
5
git commit -m "首次提交"
做什么 把暂存区里的内容打包成一个「版本」，存入本地 Git 仓库，并附上说明文字。
不做什么 仍然只存在于你的电脑上，没有上传到 Gitee。引号里的文字只是备注，不影响代码。
6
git remote add origin 你的仓库HTTPS地址 git push -u origin master
做什么 绑定远程仓库地址（origin），然后把本地 master 分支的已提交版本上传到 Gitee；-u 记住关联，以后直接 git push。
不做什么 不会自动 commit，未提交的改动不会被上传；不会拉取远程已有内容。
顺序不能乱：init → touch .gitignore → vim/重定向编辑 → add → commit → remote → push。跳步会导致推送失败。

0. 先搞清楚 Git 和 Gitee 的关系

Git 是本地版本控制工具，负责记录代码的每次修改；Gitee 是基于 Git 的代码托管平台。
简单说：Git 管本地，Gitee 管远程。下面所有命令都在本地终端（Git Bash）执行。

1. 安装与配置（只需一次）
git --version
做什么 查看 Git 是否安装成功，显示版本号即表示已安装。
不做什么 不修改任何配置，不联网，只是查看。
git config --global user.name "你的名字" git config --global user.email "你的邮箱@example.com"
做什么 设置全局用户名和邮箱，Git 在提交时会记录「是谁提交的」，建议与 Gitee 账号一致。
不做什么 不创建仓库，不上传代码，只是写进 Git 配置文件。--global 表示对这台电脑所有仓库生效。
2. 完整上传流程（逐条讲清）
# 进入你的代码文件夹后执行 git init
做什么 在当前目录初始化一个本地 Git 仓库，生成隐藏文件夹 .git，从此 Git 可以追踪此目录下的文件变化。
不做什么 不上传、不提交、不关联远程仓库；已有文件不会被删除或移动。
touch .gitignore
做什么 用 touch 创建一个空的 .gitignore 文件，准备写入需要 Git 忽略的文件或目录。
不做什么 不会自动填写内容，文件是空的；不删除磁盘上的任何文件。
vim .gitignore
做什么 用 Vim 打开 .gitignore，准备写入忽略规则。
不做什么 Vim 只是编辑器，不会自动修改文件，需要手动操作。
Vim 操作 重点 1. 按 i 进入插入模式
2. 输入忽略内容，例如：
    *.log
    *.exe
    go.mod
    go.sum
    .idea
3. 按 Esc 退出插入模式
4. 输入 :wq 保存并退出
5. 如果不想保存，输入 :q! 强制退出
重定向 备选 如果不想用 Vim，可以用重定向直接写入：
echo "*.log" > .gitignore  （覆盖写入）
echo "*.exe" >> .gitignore  （追加写入）
echo "go.mod" >> .gitignore
echo "go.sum" >> .gitignore
echo ".idea" >> .gitignore
说明：> 会清空原文件再写入，>> 在文件末尾追加内容。
git add . # 或指定文件： git add index.html
做什么 把工作区中所有新增、修改的文件（忽略文件除外）放入「暂存区」，表示这些改动即将被提交。
不做什么 不生成版本记录，不上传远程。它只是「选中」改动，真正的存档在下一步 commit。
git commit -m "首次提交：完成基础页面"
做什么 将暂存区内容打包为一个版本，永久记录在本地 Git 历史中，-m 后是本次提交的说明。
不做什么 仍然只在本地，不会出现在 Gitee 上；也不包含没有 git add 过的改动。
git remote add origin https://gitee.com/你的用户名/仓库名.git
做什么 把本地仓库与 Gitee 上的远程仓库关联，给这个远程地址起别名 origin，方便后续 push/pull。
不做什么 不传输任何代码，只是登记地址。如果提示 remote origin already exists，改用 git remote set-url origin 新地址。
git push -u origin master
做什么 把本地 master 分支的所有已提交版本上传到 Gitee 的 origin 仓库；-u 建立跟踪关系，以后直接 git push 即可。
不做什么 不会自动 commit，未提交的改动不会被上传；不会自动合并远程已有内容（若远程有 README 等需先 pull）。
如果推送被拒绝（rejected），说明远程有本地没有的提交。先执行 git pull origin master 合并，再重新 push。
3. 日常更新：改完代码后只需三条
git add . git commit -m "修改说明" git push
做什么 暂存改动 → 提交到本地 → 推送到 Gitee。因为第一次 push 用了 -u，之后可以直接 git push，无需再写 origin master。
不做什么 不需要重复 git init 和 git remote add，一个仓库只需初始化一次。
4. 常见问题
❓ push 被拒绝 (rejected)

远程仓库有你本地没有的内容（如创建时勾选了 README）。先 git pull origin master 合并，再 git push。

❓ 每次都要输密码

在 Gitee 设置里配置 SSH 公钥，把远程地址换成 SSH 格式（git@gitee.com:...），即可免密。

❓ 提交后发现漏了文件

再执行 git add 漏掉的文件 → git commit -m "补充" → git push 即可，不需要重新 init。

❓ 为什么需要 .gitignore？

避免将系统文件、日志、依赖包等无关内容上传到仓库，保持仓库干净，也防止敏感信息泄露。

❓ 不会用 Vim 怎么办？

记住三个操作：i 进入编辑模式，Esc 退出编辑模式，:wq 保存退出。如果出错想放弃修改，输入 :q! 不保存强制退出。也可以直接用重定向 echo "内容" >> .gitignore 追加写入。

创建仓库后，先别急着敲命令！

Gitee 在创建完仓库后，页面上会直接显示一段完整的命令清单，你只需要复制下来，按需修改即可，不用全部自己手写。

为什么特别提醒这一点？

很多新手创建完仓库后直接关掉页面，然后手动去敲命令，容易漏掉关键步骤（比如 git remote add origin 的地址复制错）。Gitee 页面已经为你准备好一份“标准答案”，直接复制修改最省事。

新建仓库（模拟 Gitee 页面）
my-project
https://gitee.com/yourname/my-project.git
使用 Readme 文件初始化这个仓库
使用 .gitignore 模板
使用开源许可证
创建仓库
复制这段就能用
Gitee 创建后显示的命令
# 已有仓库？直接复制下面命令并修改地址： git remote add origin https://gitee.com/yourname/my-project.git git push -u origin master # 如果还没初始化，先执行： git init git add . git commit -m "first commit" git remote add origin https://gitee.com/yourname/my-project.git git push -u origin master
怎么用这段命令？
# 第一步：复制 Gitee 页面上的 git remote add 那一行 git remote add origin https://gitee.com/yourname/my-project.git # 第二步：把地址改成你自己的仓库地址 # 注意：yourname 换成你的 Gitee 用户名，my-project 换成你的仓库名 # 第三步：推送 git push -u origin master
做什么 直接复制 Gitee 页面上给的命令，把用户名和仓库名改成自己的，就能完成关联和推送。不需要自己拼写命令，减少出错。
不做什么 不要照抄页面上的用户名和仓库名，一定要替换成你自己的；如果本地还没 git init，要先执行初始化步骤。
总结：最省事的做法

1. 在 Gitee 上创建仓库。
2. 创建完成后不要关页面，找到它显示的“已有仓库？”或“Git 命令”区域。
3. 复制命令 → 粘贴到终端 → 把用户名/仓库名改成自己的 → 执行。
4. 如果本地已有代码，先 git init、git add .、git commit -m "first commit"，再执行复制的命令。
